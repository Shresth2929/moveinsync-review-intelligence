# Data folder

Generated by the pipeline (not committed by default if empty):

| File | Contents |
|---|---|
| `reviews_clean.csv` | Normalized, deduplicated real reviews (canonical columns, original text preserved) |
| `reviews_categorized.csv` | Clean reviews + `categories` (pipe-separated), `evidence`, `confidence`, `needs_manual_review`, `rating_bucket` |
| `collection_meta.json` | Collection time, method, country, language, sort, displayed rating (if captured), cleaning stats, last collection error |
| `latest_flags.json` | Period-over-period comparison and threshold flags |
| `validation_sample.csv` | Random sample for manual labeling (`--validation-sample`) |

## Getting real data (if the scraper cannot reach Google Play)
1. **Play Console export (authorized, needs developer access):** Play Console → Ratings and reviews → Reviews → Export (CSV).
2. **Google Play Developer API `reviews.list` (authorized, needs developer access):** export results to CSV.
3. **Public copy:** run `python -m src.pipeline --collect` on a machine with internet access, or copy public reviews from the Play listing into a CSV you are permitted to use.

CSV columns (any of these names are auto-mapped): `reviewId`/`review_id`, `score`/`rating`/`stars`, `content`/`text`/`review`, `at`/`review_date`/`date`, `appVersion`/`reviewCreatedVersion`/`version`, `replyContent`, `thumbsUpCount`. Only rating (1-5) is mandatory; rows with invalid ratings are dropped and counted.

Record the displayed store rating yourself: `--displayed-rating 3.x` (read from the Play listing at import time).

No synthetic data lives in this folder. Test fixtures are generated inside `tests/` only.
